Magictory

Magictory

Un juego de automatización medieval y magia arcana.

Nombre: Magictory

Desarrollador: FranForge

Periodo: Ago 2025 - Nov 2025

Framework: Unity 6000.2.10.f2.

Sinopsis: En un mundo consumido por los seres oscuros el rey del reino te manda a ti, un simple mago de confianza que puede moldear su magia para hacer funcionar cosas, es ahí donde comienza tu aventura donde deberás construir un asentamiento capaz de albergar protecciones mágicas para que el pueblo pueda vivir libre.

Géneros y Etiquetas: Automatización, gestión de recursos, fabricación, gestión de bases, construcción.

Vídeo resumen

Sistemas Implementados

Inventario y Objetos

  • ScriptableObjects para definir tipos de recursos y ahorro de memoria.
  • Structs para representar pilas de recursos.
  • Structs en vez de clases y Arrays en vez de Listas para reducir GC.
  • Crafting: Sistema de recetas que se basa en listas de recursos requeridos y lista de estructuras que pueden fabricarlos.

Descripción

Implementé todo un sistema de objetos ScriptableObjects que definian cada tipo de recurso, luego una struct Stack contenía la referencia al tipo de recurso y un integer para la cantidad. Por último una clase Inventory tenía un array de stacks con una cantidad máxima que se definía desde el Inspector de Unity.

Sistema de Interacción

  • Sistema basado en interfaces.
  • Interacción mediante Physics.OverlapSphere.

Descripción

Sistema de interacción basado en interfaces que implementan todos los objetos con los que el jugador puede interactuar, cada objeto implementa su propia lógica y al interactuar con ellos el movimiento del jugador se bloquea mientras esta se realiza.

Sistema de Construcción

  • ActionMap exclusivo para mayor control en construcción.
  • ScriptableObjects para definir las estructuras.
  • Desbloqueo de estructuras mediante progresión.
  • Conexiones entre estructuras dependiente de otras.
  • Interfaz que define los requisitos para construir.

Descripción

Sistema de construcción basado en un ActionMap específico que habilita cámara libre y control por cursor. Las estructuras se definen mediante ScriptableObjects y se desbloquean progresivamente. Cada construcción valida sus requisitos mediante una interfaz antes de ser colocada.

Sistema propio de actualización (Tick)

  • Optimización de recursos.
  • Centralización de llamadas para reducir carga.
  • Tick cada determinado tiempo con IEnumerator y Coroutine para reducir consumo de Update.
  • Implementación de Tick mediante interfaces.
  • Separación lógica y visual, Tick solo se usa para cálculos de producción.

Descripción

Sistema de actualización basado en ticks donde un TickManager ejecuta de forma periódica la lógica de todos los objetos que implementan ITickable. Los elementos se registran en una lista y son procesados mediante Coroutine, reduciendo la dependencia de Update en cálculos frecuentes.

Segmentación de mapa (Chunks)

  • Optimización de recursos.
  • Segmentación del mapa.
  • Carga y descarga visual.

Descripción

El mapa se divide en segmentos que se cargan y descarga dependiendo de la proximidad al jugador, permite ahorrar recursos si el jugador no está cerca de zonas no visibles o relevantes.

Niveles de detalle (LODs)

  • Diferentes niveles de detalle para mayor rendimiento.

Movimiento del personaje (NavMesh)

  • Cálculo de rutas con NavMesh.
  • NavMeshObstacle para elementos del mapa dinámicos.
  • Movimiento Point and Click.
  • Diferente movimiento en ratón y mando para mayor fluidez.

Descripción

Para mover al personaje desde una vista cenital usé NavMesh de Unity para poder mover al personaje por el terreno con el cursor, más tarde implementé un movimiento normal para el mando mediante joystick.
