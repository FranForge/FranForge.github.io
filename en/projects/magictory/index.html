Systems I worked on

Items and Inventory

  • ScriptableObjects to define resource types and reduce memory usage.
  • Structs to represent resource stacks.
  • Structs instead of classes and arrays instead of lists to reduce GC.
  • Crafting: A recipe system based on lists of required resources and a list of structures that can craft them.

Description

I implemented a full ScriptableObject-based system that defined each type of resource. Then, a Stack struct contained a reference to the resource type along with an integer representing the amount. Finally, an Inventory class held an array of stacks with a maximum capacity defined through the Unity Inspector.

Interaction System

  • Interface-based interaction system.
  • Interaction detection via Physics.OverlapSphere.

Description

I implemented an interaction system based on interfaces that every interactable object must implement. Each object handles its own specific logic, while the player's movement is locked during the interaction to ensure consistency.

Building System

  • Exclusive ActionMap for precise construction control.
  • ScriptableObjects to define building structures.
  • Progression-based structure unlocking.
  • Dependencies and connections between specific structures.
  • Interface to define and validate construction requirements.

Description

The building system uses a dedicated ActionMap that enables a free camera and cursor-based control. Structures are defined through ScriptableObjects and unlocked progressively. Before placement, each building uses an interface to validate its material and spatial requirements.

Custom Tick System

  • Resource optimization through centralized calls.
  • Periodic ticks using IEnumerators and Coroutines to reduce Update load.
  • Interface-driven tick implementation (ITickable).
  • Strict separation between logic and visuals; ticks only handle production calculations.

Description

I developed a TickManager that periodically executes the logic for all objects implementing ITickable. Elements register themselves in a list and are processed via Coroutines, significantly reducing the dependency on the Update method for frequent backend calculations.

Map Segmentation (Chunks)

  • Resource optimization through map segmentation.
  • Visual loading and unloading based on player proximity.

Description

The world map is divided into segments that load or unload depending on the player's distance. This approach saves significant hardware resources by disabling non-visible or irrelevant zones.

Levels of Detail (LODs)

  • Multiple detail levels for enhanced rendering performance.

Description

I implemented various LOD levels to ensure the game maintains a high performance and stable frame rate, even with complex environments.

Character Movement (NavMesh)

  • Pathfinding calculations using Unity NavMesh.
  • NavMeshObstacles for dynamic map elements.
  • Point and Click movement system.
  • Differentiated input logic for mouse and gamepad for better fluidity.

Description

To handle character movement from a top-down perspective, I utilized Unity's NavMesh for cursor-based navigation. Later, I implemented a direct movement system for gamepads using joysticks to provide a smoother user experience across different platforms.
